Component communication: @Input and @Output

Lesson 2 put everything in one component. Real apps split UI into smaller pieces. The parent owns the data; children display it and send events back up.

1. The pattern

  • @Input — parent passes data down to a child.
  • @Output — child emits events up to the parent.
  • Data flows down, events flow up. The parent stays the single source of truth.

What you should remember

  • [task]="task" is property binding into an @Input.
  • (toggle)="onToggle($event)" listens to an @Output.
  • Children stay dumb and reusable; parents hold state and business logic.
  • One shared model file avoids duplicating interfaces.
