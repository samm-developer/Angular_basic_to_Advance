Routing guards

You reached this page because the auth guard allowed it. Guards run before a route loads — perfect for login checks and permissions.

Protected content

You are signed in. Only authenticated users see this section.

How it works

  1. User navigates to /lesson-7
  2. Router runs canActivate: [authGuard]
  3. Guard checks AuthService.isLoggedIn()
  4. If false → redirect to /login?returnUrl=/lesson-7
  5. After login → navigate back to Lesson 7

Files to read

  • auth.service.ts — login state
  • auth.guard.ts — blocks or allows the route
  • login/login.component.ts — login form
  • app.routes.ts — wires guard to route

What you should remember

  • canActivate — can user open this route?
  • Guards return true, false, or a UrlTree redirect.
  • Use a service (e.g. AuthService) to hold login state.
  • Other guards: canDeactivate, canMatch, canActivateChild.
